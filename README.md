# Стоматологическая клиника

Статический сайт стоматологической клиники, размещённый на [GitHub Pages](https://aktika-tech.github.io/admin-helper/).

## Живая версия

[https://aktika-tech.github.io/admin-helper/](https://aktika-tech.github.io/admin-helper/)

## Структура

Сайт собран на [Astro](https://astro.build) и полностью статический. Он устроен как вики: меню слева, текст страниц в Markdown, одно общее оформление.

- `src/content/pages/*.md` — страницы; имя файла становится адресом (`lechenie.md` → `lechenie.html`, `index.md` → главная)
- `src/content/doctors/*.md` — врачи, по файлу на врача (выводятся на странице «Врачи»)
- `src/content.config.ts` — какие поля допустимы в шапке (frontmatter) страниц и врачей
- `src/pages/[...slug].astro` — общий шаблон всех страниц; `src/pages/prezentaciavrachi.astro` — страница врачей
- `src/layouts/Layout.astro` — каркас: `<head>`, боковое меню, контент
- `src/components/Sidebar.astro` — боковое меню (собирается из страниц автоматически)
- `src/components/DoctorCard.astro` — карточка врача
- `src/styles/global.css` — единственный файл стилей и палитра
- `scripts/check-content.mjs` — проверка, что в контенте нет HTML-разметки и стилей
- `public/` — файлы, которые копируются как есть (`favicon.ico`, `.nojekyll`)

## Как редактировать контент

Страница — это Markdown-файл с шапкой:

```markdown
---
title: Лечение                  # заголовок страницы и вкладки
description: Короткий вводный абзац   # необязательно
nav:
  label: Лечение                # подпись в меню (по умолчанию — title)
  order: 20                     # место в меню: меньше — выше
  hidden: false                 # true — страница есть, но в меню не показывается
---

## Для детей {#deti}

### Кариес

- Стоимость лечения — **от 9 210 рублей**.
```

- Новая страница появится в меню сама, достаточно создать файл.
- Разделы (`##`) текущей страницы показываются в меню под её названием.
- `{#deti}` после заголовка задаёт якорь (`lechenie.html#deti`). Не меняйте существующие якоря, на них есть ссылки.
- Пишите только Markdown: `**жирный**`, `*курсив*`, списки, таблицы, ссылки, картинки. Классы, `style`, `<div>`, `<span>`, `<br>` запрещены — `npm run check:content` и CI их не пропустят. Если нужен перенос строки, начните новый абзац или пункт списка.
- Прайс удобно оформлять таблицей; двоеточие справа (`|---:|`) выравнивает столбец с ценами по правому краю.
- В числах между разрядами ставьте неразрывный пробел (`9 210`), чтобы цена не разрывалась на две строки.
- Картинки кладите в `src/content/pages/images/` и вставляйте относительным путём: `![Описание](./images/имя.jpg)`. Astro сам сожмёт их и подставит правильный адрес (в том числе для превью PR).

Врач — файл `src/content/doctors/<id>.md`; `<id>` становится якорем (`prezentaciavrachi.html#krutikova`):

```markdown
---
name: Крутикова Елена Анатольевна
photo: ./images/krutikova.jpg
order: 10            # порядок на странице
prodoctorov: true    # абзац про «ПроДокторов» в конце карточки
---

**Елена Анатольевна** — стоматолог-имплантолог…
```

## Оформление

Все стили — в `src/styles/global.css`, цвета заданы переменными:

| Переменная | Цвет | Где используется |
|---|---|---|
| `--color-primary` | `#00524d` | меню, заголовки, ссылки |
| `--color-accent` | `#ff7300` | фирменный цвет: активный пункт меню, наведение, фокус |
| `--color-text` | `#363E45` | основной текст |
| `--color-support` | `#97C261` | маркеры списков, линии таблиц, разделители |

Оранжевый не используйте для текста на белом фоне: он плохо читается.

## Локальный запуск

Нужен Node.js 22.23+ (в CI используется Node 24).

```bash
npm install
npm run dev      # http://localhost:4321/admin-helper/
npm run build    # сборка в dist/
npm run check:content  # проверка Markdown-контента
npm run preview  # просмотр собранного сайта
```

## Публикация

Сайт собирается и публикуется GitHub Actions в ветку `gh-pages`:

- пуш в `main` собирает сайт и выкладывает `dist/` в корень (`.github/workflows/deploy.yml`);
- каждый пул-реквест получает превью по адресу `/pr-preview/pr-N/`, ссылка появляется комментарием в PR (`.github/workflows/preview.yml`). Для превью базовый путь задаётся переменной `BASE_PATH`.

В настройках Pages источником должна быть ветка `gh-pages`. Файл `public/.nojekyll` нужен, чтобы GitHub не прятал папку `_astro/`.
